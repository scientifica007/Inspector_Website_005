# بروتوكول القبول البشري (Human Acceptance Protocol)

الاختبارات الآلية تمر، لكن ذلك **ليس** إعلانًا بالجاهزية النهائية. هذا الملف هو
قائمة الاختبار البشري التي تغطي المنتج على الحاسوب والهاتف. بعد كل جلسة اختبار
صنّف النتائج كما في القسم الأخير.

## قبل البدء

```bash
source .venv/bin/activate
python manage.py migrate
python manage.py seed_demo
python manage.py runserver 0.0.0.0:8000
```

افتح `http://127.0.0.1:8000/` على الحاسوب، وافتح `http://<عنوان-جهازك>:8000/` من
الهاتف على الشبكة نفسها (مرّر `DJANGO_ALLOWED_HOSTS` كما في README).

حسابات العرض: `admin / admin-demo-123` و `inspector / inspector-demo-123`.

## A. الأساسيات والتوجيه

| # | الاختبار | المتوقع |
| --- | --- | --- |
| A1 | افتح أي صفحة على الحاسوب | اتجاه من اليمين إلى اليسار، والنص العربي سليم غير مقلوب |
| A2 | افتح الصفحة نفسها على الهاتف | لا تمرير أفقي غير ضروري، والقائمة تعمل |
| A3 | افتح أي نموذج يحتوي تاريخًا | يظهر `dd/mm/yyyy`، أو منتقٍ يمنع الالتباس |
| A4 | سجّل الدخول بمستخدم مفتش | ترى «زياراتي» و«تكليفاتي»، ولا ترى روابط الأدلة والتكليف الإداري |
| A5 | سجّل الدخول بمستخدم مدير | تظهر مساحات الحوكمة (الأدلة، التكليفات، مقترحات التعميم، المستخدمون) |

## D. إنشاء الزيارة واللقطة المجمّدة

| # | الاختبار | المتوقع |
| --- | --- | --- |

## G. الأدلة

| # | الاختبار | المتوقع |
| --- | --- | --- |
| G1 | كمدير: أنشئ دليلًا مرتبطًا بمرجع وانشره، وأضف أهدافًا | الدليل متاح للمفتش داخل زيارات المرجع نفسه |
| G2 | كمفتش: طبّق الدليل على مسودة متوافقة | تُضاف العناصر الناقصة فقط، بمصدر **دليل** |
| G3 | طبّق الدليل نفسه مرة ثانية | **لا تتكرر** العناصر ولا تُضاف عناصر جديدة |
| G4 | اختر عنصرًا يدويًا، ثم طبّق دليلًا يشمله | يبقى مصدر العنصر **يدوي** ولا يتغير |
| G5 | لاحظ أي عنصر دخل بالدليل | **ليس مقفلًا**، وليس متطلب إتمام |
| G6 | كمدير: عدّل الدليل أو احذفه بعد التطبيق | الزيارة السابقة **لا يُعاد كتابتها** |

| # | الاختبار | المتوقع |
| --- | --- | --- |
| H1 | كمدير: أنشئ تكليفًا (مسودة) وأضف بندًا يستهدف عنصرًا في مسودة زيارة | **لا يظهر للمفتش** |

## تصنيف النتائج

عند إرسال نتائجك، صنّف كل اختبار إلى:

| التصنيف | المعنى |
| --- | --- |
| **PASS** | يعمل كما هو موصوف تمامًا. |
| **TECHNICAL-PASS** | يعمل، لكن مع ملاحظة تجربة استخدام لا تمسّ السلوك (ترتيب، تسمية، …). |
| **RETEST** | لم أستطع الحكم، أو النتيجة متذبذبة؛ يحتاج إعادة اختبار. |
| **DEFECT** | لا يعمل كما هو موصوف؛ عيب حقيقي يحتاج إصلاحًا. |
| **UNCERTAIN** | غير واضح إن كان المتوقع صحيحًا من الأساس؛ يحتاج توضيحًا. |

بعد التصنيف سأحدد فقط الاختبارات الضرورية المتبقية، وأعالج الـ DEFECTs، وأعيد
الاختبارات المتأثرة.
